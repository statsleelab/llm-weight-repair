Blind Weight Repair:
Can a Frontier LLM Fix a Damaged Language Model by Editing Its Weights?

__AUTHOR__ · __AFFILIATION__ · November 2026

Abstract — We took a small language model (GPT-2), deliberately broke some of its weights, and handed the broken file to four Claude models (Fable, Opus, Sonnet, Haiku). Each had to work out what was wrong and write better numbers into the file by hand: no copy of the original, no downloads, no retraining. The best model brought the broken model back to near-normal in three of four kinds of damage. What it contributed was finding the damage. Guessing the lost values turned out to matter much less.

§1 · The Idea

A Book With Smudged Letters, and No Second Copy

A language model is, physically, a file of numbers called weights. GPT-2 has 124 million of them. Nobody wrote those numbers: they were found by training. Our earlier work reproduced a surprising result: a frontier LLM can read and write the weights of small networks directly, the way a programmer edits code.

This study asks the next question. Suppose the file gets damaged, so that some of the numbers are wrong. Can a frontier LLM look at the damaged file and fix it? Think of a book in which one letter in a hundred has been smudged, and there is no second copy. A careful reader can often spot the smudges and write in something sensible. We tested whether an LLM can do the same for a neural network.

The rule that makes it hard: the repairing model never sees the answer. It gets only the damaged file. It cannot download the original, and it cannot retrain the model. It can read the numbers, run the broken model to see how it misbehaves, do statistics, and then write new numbers.

글자가 번진 책, 그리고 사본은 없다

언어 모델은 물리적으로는 가중치라고 부르는 숫자들이 담긴 파일입니다. GPT-2에는 1억 2,400만 개가 있습니다. 이 숫자는 누가 쓴 것이 아니라 학습으로 찾아낸 것입니다. 이전 연구에서 우리는 놀라운 결과 하나를 재현했습니다. 프런티어 LLM은 프로그래머가 코드를 고치듯 작은 신경망의 가중치를 직접 읽고 쓸 수 있습니다.

이번 연구는 그다음 질문을 던집니다. 파일이 손상돼 숫자 일부가 틀려졌다고 합시다. 프런티어 LLM이 그 손상된 파일을 보고 고칠 수 있을까요? 백 글자 중 한 글자가 번졌는데 사본이 없는 책을 떠올리면 됩니다. 주의 깊은 독자는 번진 곳을 찾아내 그럴듯한 글자를 써 넣을 수 있습니다. LLM이 신경망에 대해 같은 일을 할 수 있는지 시험했습니다.

이 과제를 어렵게 만드는 규칙: 복구하는 모델은 정답을 절대 보지 못합니다. 손상된 파일만 받습니다. 원본을 내려받을 수 없고 모델을 다시 학습시킬 수도 없습니다. 숫자를 읽고, 망가진 모델을 돌려 어떻게 오작동하는지 보고, 통계를 낸 뒤, 새 숫자를 써 넣을 수 있을 뿐입니다.

§2 · Experimental Setup

Three Steps: Break It, Repair It Blind, Score It Fairly

세 단계: 망가뜨리고, 블라인드로 고치고, 공정하게 채점한다

① Break① 손상

We corrupt 1% of the entries in each of GPT-2's 50 weight matrices. Then we lock away everything that could give the answer: the original weights, the list of damaged entries, and the test data. All of it is encrypted while the repair runs.

GPT-2의 가중치 행렬 50개 각각에서 항목의 1%를 망가뜨립니다. 그런 다음 정답이 될 수 있는 것을 모두 잠급니다. 원본 가중치, 손상된 항목 목록, 테스트 데이터를 복구가 진행되는 동안 암호화해 둡니다.

② Repair blind② 블라인드 복구

Each Claude model works alone in a folder with the damaged file, a short program that runs GPT-2, and a page of practice text. It is told only: "about 1% of the entries are wrong." It may use statistics and linear algebra. It may not train, and it has about 40 minutes.

각 Claude 모델은 손상된 파일, GPT-2를 실행하는 짧은 프로그램, 연습용 텍스트 한 편만 있는 폴더에서 혼자 작업합니다. 알려 주는 것은 "항목의 약 1%가 틀렸다"뿐입니다. 통계와 선형대수는 쓸 수 있지만 학습은 할 수 없고, 시간은 약 40분입니다.

③ Score③ 채점

After every run has ended we unlock the answer key and test each repaired model on text it never saw: perplexity on Wikipedia articles, a grammar test (BLiMP) and a facts test (capital cities). We also compare every repaired number with the original.

모든 실행이 끝난 뒤 정답을 풀고, 복구된 모델을 한 번도 보지 못한 글로 시험합니다. 위키백과 글의 perplexity, 문법 시험(BLiMP), 사실 시험(수도 맞히기)입니다. 복구된 숫자 하나하나를 원본과도 비교합니다.

We ran this for four Claude models on four kinds of damage (16 runs), and later on three harder cases (12 more runs). Every script each model wrote, and its own report, is in the repository.

네 개의 Claude 모델과 네 가지 손상에 대해 실행했고(16회), 나중에 더 어려운 세 경우를 추가했습니다(12회). 각 모델이 작성한 스크립트와 자체 보고서는 모두 저장소에 있습니다.

§3 · Four Kinds of Damage

Where the Damage Sits, and Whether It Leaves a Mark

Two questions define each kind of damage. Where? Either scattered at random, like specks of dust, or in one solid rectangle per matrix, like a torn-out paragraph. What happens to the numbers? Either they are erased to exactly zero, or they are replaced by random noise. The difference matters: a zero is easy to spot, because trained weights are almost never exactly zero. Noise leaves no such mark.

손상이 어디에 있고, 흔적을 남기는가

손상의 종류는 두 가지 질문으로 정해집니다. 어디에? 먼지처럼 무작위로 흩어져 있거나, 찢겨 나간 문단처럼 행렬마다 직사각형 하나로 뭉쳐 있습니다. 숫자가 어떻게 되는가? 정확히 0으로 지워지거나, 무작위 노이즈로 바뀝니다. 이 차이가 중요합니다. 학습된 가중치는 정확히 0인 경우가 거의 없어서 0은 쉽게 눈에 띕니다. 노이즈는 그런 흔적을 남기지 않습니다.

A · Scattered erasureA · 산발 소거

Random entries set to zero. Easy to find, and yet the model collapses completely.

무작위 항목이 0이 됩니다. 찾기는 쉽지만 모델은 완전히 붕괴합니다.

B · Scattered noiseB · 산발 노이즈

Random entries get large random values added. Nothing marks them. The hardest case.

무작위 항목에 큰 무작위 값이 더해집니다. 아무 표시가 없습니다. 가장 어려운 경우입니다.

C · Block erasureC · 블록 소거

One rectangle per matrix set to zero. Obvious at a glance. The easiest case.

행렬마다 직사각형 하나가 0이 됩니다. 한눈에 보입니다. 가장 쉬운 경우입니다.

D · Block noiseD · 블록 노이즈

One rectangle per matrix overwritten with noise the same size as real weights. Invisible to simple statistics.

행렬마다 직사각형 하나가 실제 가중치와 같은 크기의 노이즈로 덮입니다. 단순한 통계로는 보이지 않습니다.

How bad is each kind before any repair?복구 전에는 얼마나 나쁜가?

Healthy GPT-2 on the same tests: perplexity 28.9, grammar 0.830, capitals 0.563. Scattered damage is far more destructive than block damage of the same size, because it reaches every row of every matrix.

같은 시험에서 정상 GPT-2는 perplexity 28.9, 문법 0.830, 수도 0.563입니다. 같은 양이라도 산발 손상이 블록 손상보다 훨씬 파괴적입니다. 모든 행렬의 모든 행에 닿기 때문입니다.

§5 · How Much of This Needs an LLM?

The Hard Part Is Finding the Damage, Not Filling It In

A fair question: could a short ordinary script do the same job? We tested that with simple scripts, and with one script that cheats: we tell it exactly which entries are damaged, and it fills each with the average of its column. That cheating script is not a competitor. It is a yardstick for what perfect detection plus a crude fill is worth.

어려운 것은 손상을 찾는 일이지, 채우는 일이 아니다

당연한 질문이 있습니다. 짧은 일반 스크립트로도 같은 일을 할 수 있지 않을까요? 단순한 스크립트들로 시험했고, 반칙을 하는 스크립트도 하나 넣었습니다. 어떤 항목이 손상됐는지 정확히 알려 주고, 각 항목을 그 열의 평균으로 채우게 한 것입니다. 이 반칙 스크립트는 경쟁자가 아닙니다. "완벽한 탐지 + 거친 채우기"가 어느 정도인지 재는 잣대입니다.

§6 · Follow-Up: More Damage, Stronger Scripts

From 0.1% to 30% Damage: Where Scripts Stop Working

The first round raised two doubts. Is 1% a special amount? And were our scripts too weak to be a fair comparison? So we wrote stronger automatic scripts, ran them at five damage levels, and then sent the four Claude models into the three cases where the scripts fell furthest short.

  • Best automatic script. It tries four repair recipes (fill zeros, two outlier detectors, a search for odd-looking rectangles) and keeps whichever makes the practice text read best.
  • Ceiling. The same repair when we tell the script where the damage is. No blind method should beat this by much. The distance between a repair and the ceiling is the price of not knowing where the damage is.

손상 0.1%에서 30%까지: 스크립트가 멈추는 곳

첫 실험은 두 가지 의문을 남겼습니다. 1%가 특별한 양인가? 우리 스크립트가 공정한 비교가 되기에는 너무 약했던 것 아닌가? 그래서 더 강한 자동 스크립트를 만들어 다섯 가지 손상 수준에서 돌렸고, 스크립트가 가장 크게 뒤처진 세 경우에 네 개의 Claude 모델을 투입했습니다.

  • 최선의 자동 스크립트. 네 가지 복구 방법(0 채우기, 이상치 탐지 두 가지, 이상해 보이는 직사각형 탐색)을 시도하고, 연습용 텍스트를 가장 잘 읽게 만드는 것을 고릅니다.
  • 상한. 손상 위치를 스크립트에 알려 주었을 때의 같은 복구입니다. 블라인드 방법이 이를 크게 넘을 수는 없습니다. 복구 결과와 상한 사이의 거리가 "손상 위치를 모르는 대가"입니다.

Erasure: no LLM needed소거: LLM이 필요 없음

At every damage level the script sits right on the ceiling, because zeros show where the damage is. What gets worse is the ceiling itself: about 40 at 3%, around 200 at 10%, unusable at 30%. Beyond a point, too much is simply gone.

0이 손상 위치를 보여 주므로 모든 손상 수준에서 스크립트가 상한과 같습니다. 나빠지는 것은 상한 자체입니다. 3%에서 약 40, 10%에서 200 안팎, 30%에서는 쓸 수 없습니다. 어느 선을 넘으면 사라진 것이 너무 많습니다.

Noise blocks: Fable matches the ceiling노이즈 블록: Fable이 상한에 도달

At 3% damage Fable scored 40.3 against a ceiling of 40.0, with 99.7% of its edits landing on damaged entries. The best script managed 67.3. Bigger blocks were easier to find: Opus and Sonnet located almost all of them at 3%. Haiku found nothing at either level and said so.

3% 손상에서 Fable은 상한 40.0 대비 40.3이었고, 수정의 99.7%가 손상 항목에 적중했습니다. 최선의 스크립트는 67.3이었습니다. 블록이 클수록 찾기 쉬워서 3%에서는 Opus와 Sonnet도 거의 다 찾았습니다. Haiku는 두 수준 모두에서 아무것도 찾지 못했고 그렇게 보고했습니다.

Scattered noise: still unsolved산발 노이즈: 아직 미해결

No script produced a working model at any level, not even 0.1%, although the ceiling there is 32.6. Fable reached 53.6 at 0.1%, 86.7 at 1% and 1,426 at 3%. It is the only repair that works at all, and it falls further behind as damage grows.

어떤 스크립트도 어떤 수준에서도 작동하는 모델을 만들지 못했습니다. 상한이 32.6인 0.1%에서도 그랬습니다. Fable은 0.1%에서 53.6, 1%에서 86.7, 3%에서 1,426이었습니다. 그나마 작동하는 유일한 복구이지만, 손상이 커질수록 더 뒤처집니다.

So where does the hypothesis hold? A frontier model adds something scripts did not exactly where the damage leaves no mark. When the hidden damage has a shape to find (a block), the model does as well as if it had been told the answer. When the hidden damage is scattered and blends into the natural spread of the weights, the model beats the scripts but stays well short of the ceiling.
그래서 가설은 어디에서 성립하는가? 손상이 흔적을 남기지 않는 바로 그 지점에서 프런티어 모델은 스크립트가 하지 못한 일을 합니다. 숨은 손상에 찾아낼 형태(블록)가 있으면 모델은 정답을 들은 것만큼 잘합니다. 숨은 손상이 흩어져 가중치의 자연스러운 분포에 섞이면, 모델은 스크립트보다 낫지만 상한에는 한참 못 미칩니다.

Why is scattered noise so stubborn?

GPT-2 has a weak spot. The table that turns words into numbers is also used, in reverse, to choose the next word. A few columns of that table hold almost the same value for every word, and the model multiplies them by a large factor. One wrong entry in such a column makes one word win every prediction, which is why a damaged model repeats a single word forever. The scripts flagged a quarter to three quarters of the noisy entries, but the model stays collapsed unless nearly every wrong entry in those few columns is caught. Fable's reports show it identified those columns, explained why they dominate, and treated them separately. That insight came from running the broken model and reasoning about what it said.

산발 노이즈는 왜 이렇게 끈질긴가?

GPT-2에는 약점이 있습니다. 단어를 숫자로 바꾸는 표가, 거꾸로 다음 단어를 고르는 데에도 쓰입니다. 그 표의 몇몇 열은 모든 단어에 대해 거의 같은 값을 가지며, 모델은 그 열에 큰 배수를 곱합니다. 그런 열에서 항목 하나가 틀리면 한 단어가 모든 예측을 차지합니다. 손상된 모델이 한 단어만 끝없이 반복하는 이유입니다. 스크립트도 노이즈 항목의 4분의 1에서 4분의 3은 표시했지만, 그 몇 개 열의 잘못된 항목을 거의 전부 잡지 못하면 모델은 붕괴 상태로 남습니다. Fable의 보고서를 보면 그 열들을 찾아내고, 왜 그 열이 지배적인지 설명하고, 따로 처리했습니다. 이 통찰은 망가진 모델을 돌려 보고 그 출력을 해석하는 데서 나왔습니다.

§7 · Function vs Weights

The Model Works Again, but the Original Numbers Are Mostly Gone

It is tempting to imagine the repair as putting the right numbers back. That is mostly not what happened. The table compares each best repair with the hidden original. 1.00 means the damaged entries are as wrong as before; 0 means perfectly restored.

모델은 다시 작동하지만, 원래 숫자는 대부분 사라졌다

복구를 "맞는 숫자를 되돌려 놓는 일"로 상상하기 쉽습니다. 실제로는 대체로 그렇지 않았습니다. 아래 표는 가장 좋은 복구를 숨겨 둔 원본과 비교한 것입니다. 1.00은 손상 항목이 전과 똑같이 틀렸다는 뜻이고, 0은 완벽한 복원입니다.

Only the position table could be rebuilt almost exactly, because it changes smoothly from one position to the next. The word table is partly predictable from similar words. The attention and MLP matrices are close to unpredictable from their own statistics, and the models said so in their reports.

What this means: a neural network tolerates a small share of its weights being set to merely reasonable values. What it does not tolerate is a small share being wildly wrong. So a good repair is mostly finding the bad entries and neutralising them. Column B reads differently: its noise is ten times larger than the weights, so just deleting a noisy entry removes most of the error without recovering the value underneath.

거의 정확히 재구성된 것은 위치 표뿐입니다. 위치에 따라 매끄럽게 변하기 때문입니다. 단어 표는 비슷한 단어로부터 부분적으로 예측됩니다. 어텐션과 MLP 행렬은 자체 통계만으로는 거의 예측되지 않으며, 모델들도 보고서에 그렇게 적었습니다.

이것이 뜻하는 바: 신경망은 가중치의 작은 일부가 "그럴듯한 값"으로만 채워져도 견딥니다. 견디지 못하는 것은 작은 일부가 터무니없이 틀린 경우입니다. 그래서 좋은 복구는 대부분 나쁜 항목을 찾아 무력화하는 일입니다. B 열은 다르게 읽어야 합니다. 노이즈가 가중치보다 10배 커서, 노이즈 항목을 지우기만 해도 그 밑의 값을 되찾지 않은 채 오차 대부분이 사라집니다.
§8 · Limits of This Study

What These Results Do Not Show

About the evidence

  • One run per case. 28 runs, one random seed, no repeats. Large gaps are real; gaps of a few percent may be luck.
  • One small, old model. We used GPT-2 because the run environment could not reach the sites that host Qwen and Gemma. GPT-2's weak spot (§6) shapes these results, and newer models may behave differently.
  • Small tests. The capitals test has 80 questions. The follow-up used a reduced test set.
  • The follow-up is partial. Models ran only on noise damage at 0.1%, 1% and 3%.

About fairness

  • "Scripts fail" means our scripts. They were written in an afternoon, after the first-round reports had been read, by the same model family that ran the experiment. A script that copies Fable's handling of the weak spot would probably do much better. Our claim is that the model worked this out unaided, not that no script could.
  • Isolation was by rule and audit, not by a sealed box. The answer key was encrypted during the runs and the saved scripts contain no downloads or training code, but the models shared one networked machine.
  • Practice text was used for choosing. Models could compare a few candidate repairs on it. All reported scores use separate test text.
  • Time limits were requests. One run took 78 minutes instead of 40.

이 결과가 보여 주지 않는 것

근거에 관하여

  • 경우당 실행 1회. 28회 실행, 시드 하나, 반복 없음. 큰 차이는 실제이지만 몇 퍼센트 차이는 우연일 수 있습니다.
  • 작고 오래된 모델 하나. 실행 환경에서 Qwen과 Gemma를 받을 수 있는 사이트에 접근할 수 없어 GPT-2를 썼습니다. GPT-2의 약점(§6)이 결과에 영향을 주며, 최신 모델은 다르게 행동할 수 있습니다.
  • 작은 시험. 수도 시험은 80문항입니다. 후속 실험은 축소한 테스트 세트를 썼습니다.
  • 후속 실험은 부분적입니다. 모델은 노이즈 손상의 0.1%, 1%, 3%에서만 실행했습니다.

공정성에 관하여

  • "스크립트가 실패했다"는 우리 스크립트에 대한 말입니다. 첫 실험의 보고서를 읽은 뒤, 실험을 진행한 것과 같은 계열의 모델이 반나절 동안 작성했습니다. Fable의 약점 처리 방식을 그대로 옮긴 스크립트라면 훨씬 나을 것입니다. 우리의 주장은 모델이 이를 도움 없이 알아냈다는 것이지, 어떤 스크립트로도 불가능하다는 것이 아닙니다.
  • 격리는 밀폐된 상자가 아니라 규칙과 감사로 했습니다. 실행 중 정답은 암호화돼 있었고 남은 스크립트에 다운로드나 학습 코드는 없지만, 모델들은 네트워크가 열린 한 대의 머신을 공유했습니다.
  • 연습용 텍스트가 선택에 쓰였습니다. 모델은 몇 개의 후보 복구를 그 텍스트로 비교할 수 있었습니다. 보고한 점수는 모두 별도의 테스트 텍스트 기준입니다.
  • 시간 제한은 요청이었습니다. 한 실행은 40분이 아니라 78분이 걸렸습니다.
§9 · Reproducibility Guide

Run It Yourself

The repository holds the damage code, the task brief given to each model, every script the models wrote with their reports, and all scores. Damage uses a fixed seed, so the same damaged files are rebuilt exactly.

직접 실행하기

저장소에는 손상 코드, 각 모델에게 준 과제 설명, 모델이 작성한 모든 스크립트와 보고서, 전체 점수가 있습니다. 손상은 고정 시드를 쓰므로 같은 손상 파일이 정확히 다시 만들어집니다.

git clone https://github.com/statsleelab/llm-weight-repair.git
cd llm-weight-repair
pip install -r requirements.txt
bash scripts/fetch_assets.sh              # GPT-2, WikiText-2, BLiMP

python src/prepare.py assets secret       # healthy + 4 damaged checkpoints
# give agent_kit/ + one damaged file to a repair agent (see agent_kit/TASK.md), then:
python src/evaluate_runs.py assets secret runs stage results/results.json

# follow-up: script grid across damage levels, extra cases, reduced-suite scores
python src/dose_response.py assets secret/clean.safetensors results/dose_response.json
python src/make_cells.py secret/clean.safetensors stage secret
python src/score_llm_lite.py assets secret runs results/llm_lite.json
